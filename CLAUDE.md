# CLAUDE.md — Wavr

## What This Project Is

Wavr is an interactive animated gradient editor — think Unicorn Studio. Users build moving gradients of light and effects in a visual editor, then export as PNG/GIF/WebM, code (CSS, React, web component) or embeds. See `PRD.md` for the product spec, `ROADMAP.md` for what's next, `docs/` and `specs/` for design notes. `.context/HANDOFF.md` predates the monorepo; trust the code over it.

## Rendering Architecture (`packages/core/src/engine.ts`)

One pipeline for every scene: each visible layer is drawn into ping-pong composite targets by its **layer program**, then one **post program** applies the global effects to the composited image and writes the final target (canvas, feedback FBO or capture FBO). With Cinematic Bloom (`realBloomEnabled`) a bloom pyramid is built between the two (below). Targets are RGBA16F where the GPU can render to them (RGBA8 otherwise), so deband and tone mapping see unquantized colour.

Shaders (`packages/core/src/shaders/`) are assembled by string concatenation in `shader-sources.ts`; the parts are `common.glsl` (uniforms, noise, `getGradientColor`, soft-gradient helpers, SDF masks), `mouse.glsl`, `gradients.glsl`, `layer.glsl`, `post.glsl`.
- **Layer programs:** one per gradient type, compiled with `#define WAVR_GRADIENT <shader id>`. Each gradient function in `gradients.glsl` sits in an `#if WAVR_GRADIENT == <id>` guard, so a program holds exactly one of them. Layer main calls `computeGradient()` once; it also does parallax, distortion map, the 3D raymarch (finds the surface UV first), image blend, mask, opacity and the blend over `u_compositePrev`.
- **Post program:** one, with no gradient code. Neighbour-sampling effects (bloom, glow, blur, radial blur, chromatic aberration, pixel sort) are fetches of the composited scene through `sampleScene()`. The reaction-diffusion palette and `u_speed` come from the last visible layer.
- **Why:** the old uber shader called the gradient dispatcher from ~70 sites; the compiler inlined all of them (494 KB translated), and the first draw took ~100 s on SwiftShader and froze the main thread or tripped the GPU watchdog elsewhere. Keep gradient code out of post, call `computeGradient` once, and never re-evaluate a gradient for a neighbour tap.
- **Lazy, cached compile:** `layerPrograms` holds a program per gradient id (plus `custom`), created the first time a visible layer needs it. With `KHR_parallel_shader_compile` nothing blocks: `render()` draws nothing and returns false (the last frame stays on screen) until every program the frame needs has linked. See `isReady(state)`, `isCompiling()` and `getMetrics().pendingPrograms`. Don't call `getProgramParameter(LINK_STATUS)` or `getShaderParameter` before `COMPLETION_STATUS_KHR` is true; they block. `capturePixels` / `captureImageData` force completion so exports are never blank. A compile or link failure throws with the info log (the render loop stops and calls `onError`); errors read `ERROR: <file>:<line>`, numbered per file in `shader-sources.ts`.
- **Custom GLSL:** `setCustomShader()` compiles (synchronously, to report errors) a layer program whose `customGradient` is the user's code. While set, every layer uses it. Only the helpers in `common.glsl` / `mouse.glsl` are available to it, not the built-in gradient functions.
- **Context restore:** `initProgram()` drops every program, FBO and texture; programs are recompiled on demand.
- **Cinematic bloom:** `renderBloomPyramid()` runs `bloom-down.glsl` from the composited scene down a chain of half-size levels (Jimenez's 13-tap filter; the first pass converts to linear light and keeps what is above a soft threshold, reading the drawn corner like `compositeUV()`), then `bloom-up.glsl` back up, each level tent-blurred and added (blend ONE, ONE, weighted by `BLOOM_LEVEL_FALLOFF`) into the one above. The post pass samples the top level (unit 8) and adds it in linear light as an exposure, `1 - (1 - c) e^-bloom`, before the colour grade. The levels are sized from the canvas, half-float where the composite targets are, and freed when bloom is off.
- **Palette:** `getGradientColor(t)` is one fetch of the layer's baked 512×1 RGBA16F table on unit 7 (`packages/core/src/palette.ts` bakes it on the CPU: `stopCurve`, a cubic through the stops in Oklab, flat at both ends for `pingPong()`, with Catmull-Rom tangents at the inner stops so the colour never rests on one, except in a channel that repeats, peaks or dips there, so a repeated stop holds its colour, the only way to hold one since stops have no positions; then the 7-tap blend; `portable-runtime.ts` ports it), re-baked only when the stops, softness or the Oklab switch change. `u_colors` holds the raw stops, which the light fields read as lights (`lightStops`).
- **Colour profile:** `colorProfile` (`"srgb"`, the default, or `"display-p3"`) says how a scene's colour values are read, as Figma's document profile does: in P3 the same numbers are Display P3 coordinates. The engine presents the canvas in it (`drawingBufferColorSpace`; browsers without it show the values as sRGB). Nothing else in the pipeline changes, since the numbers are the same; what depends on primaries does: the Oklab palette bake and Randomize's hue turn (`bakePalette` and `rotateHue` in `palette.ts`, P3 ↔ sRGB matrices). Display P3 shares sRGB's transfer curve, so `srgbToLinear` / `lightToDisplay` serve P3 values as they are. Uploaded pictures are converted into the profile on upload (`unpackColorSpace`, cached per profile); distortion maps are data and never are. `captureImageData` tags its `ImageData` with the profile: the PNG export keeps P3 (an embedded profile), the GIF export converts to sRGB, code exports present a P3 canvas, and CSS exports write an sRGB fallback before a `color(display-p3 …)` one.
- **HDR output:** `hdrHeadroom` (stops, 0–3; 0, the default, is standard range) lets light rise above white on an HDR screen. `u_hdrPeak` (layer and post programs) is `hdrPeak(hdrHeadroom)` for a live frame going to an HDR output and 1 otherwise; read it through `framePeak()` (linear light) and `displayPeak()` (its extended-sRGB display value) in `common.glsl`. The light fields multiply their light, not their wall or room, by `framePeak()`, and `lightToDisplay()` rolls off under the peak; the bloom threshold scales with it and the bloom composite eases into it (`P - (P - c) e^(-bloom / P)`). All of these scale together, so an HDR frame is the standard one with its light P times brighter. Layer and post clamp to `displayPeak()`. WebGL can't present such a frame yet (`drawingBufferToneMapping` is an unshipped proposal), and a canvas hands on only 8 bits a channel (every float path out of WebGL clamps; a pixel that isn't opaque gets premultiplied). So with an `HdrOutput` attached (`setHdrOutput`), every live frame is drawn into a canvas-sized half-float target. `hdr-pack.glsl` packs it onto the canvas as two opaque 8-bit tiles (12 bits a channel plus alpha), each handed over as soon as it is drawn. `WebGPUHdrOutput` (`webgpu-hdr-output.ts`, the `@wavr/core/webgpu-hdr-output` subpath, kept out of the main entry so its WebGPU code loads on demand) copies them with `copyExternalImageToTexture` and decodes them onto an `rgba16float` canvas with `toneMapping: "extended"` in the scene's profile. While presenting, the WebGL canvas's `drawingBufferColorSpace` stays `"srgb"` (it holds data). Captures and exports are standard range. If WebGL ships extended-range canvases, only the transport changes.
- **Render scale:** layers can draw into the lower-left corner of the full-size composite targets at a reduced scale (`setRenderScale`, or the adaptive controller in `render-scale.ts` in the editor's auto mode); the post pass is always full size and reads them through `compositeUV()`. `u_resolution` is the layer-pass size in layer programs and the canvas size in post. Gradients that read `gl_FragCoord`, images and Custom GLSL always draw at full resolution (`FULL_RESOLUTION_GRADIENTS`); a text mask keeps the scale ≥ 0.8. Captures and exports always render at 1.
- **Pointer:** the pointer reaches gradients only through `mouseWarp()` (`mouse.glsl`), called once in layer main (not on a 3D surface uv); gradient bodies must not read `u_mouse*`. Each type picks a style (push, lens, swirl, wave) via a `WAVR_MOUSE_WARP` line; all are aspect-correct, local (~0.26 canvas heights), zero when the pointer is absent (`u_mousePresence`) and calibrated to the same strength per `mouseReact`. `pointer.ts` holds the critically damped smoother, presence and velocity (canvas heights per second); `advancePointer(dt)` steps it, the click ripple and the trail on real seconds, also while paused.

Per-layer params (type, colors, speed, masks, images, …) live on each layer. Global effects live on the store root.

## Rules That Are Easy To Break

- **Uniforms:** set layer/post-program uniforms only through `setf` / `seti` / `set2f` / `setMat4` (and the `u_colors` loop in `setPalette`). They upload to the program last bound with `useProgram()` and skip unchanged values via a per-location cache; locations belong to one program, and `disposeProgram()` drops its entries. A raw `gl.uniform*` call on those programs desyncs the cache. A uniform must also be listed in `PROGRAM_UNIFORM_NAMES`, or it is silently never set (a test checks this against the GLSL).
- **Reading pixels:** don't read pixels from the WebGL canvas (`toBlob`, `toDataURL`, `drawImage`). The editor uses `preserveDrawingBuffer: false`, so the buffer is blank after presentation. Use `engine.captureImageData({ state, time, width, height })`. It renders offscreen at render scale 1 and restores the live clock, canvas size, scale and state. The 3D overlay has the same constraint; use the `SceneCapture` function from `Scene3DCanvas`.
- **Sampler units:** never leave a texture bound to a sampler unit while rendering into it (a WebGL feedback loop). Each sampler has a fixed unit (0 prev frame, 1 image, 2 distortion map, 3 text mask, 4 trail, 5 previous layers, 6 scene, 7 palette, 8 bloom; the trail and bloom programs use 0 for their source). `render()` unbinds 5/6 before each layer draw, and the post pass unbinds what it bound.
- **Colour profiles:** a P3 frame put on a 2D canvas without `{ colorSpace: frame.colorSpace }` is silently converted to sRGB (clipped); keep the frame's space unless you mean to convert. Anything that converts colours (Oklab, luminance, CSS) must not assume sRGB primaries in a P3 scene. A patch that brings colours without naming a profile is sRGB (`loadPreset`).
- **Render loop:** use `requestAnimationFrame`, never `setInterval`. That goes for export capture loops too.
- **HDR:** at `u_hdrPeak` 1 every shader path must stay today's arithmetic: standard range is bit-identical to before HDR (snapshot diff 0/255), so guard HDR-only changes with `u_hdrPeak > 1.0` where an expression would otherwise change. The brightest value a frame may hold is `displayPeak()`, not 1.0. Code exports swap `framePeak()`, `displayPeak()` and `peakShoulder()` for their standard-range forms (`STANDARD_RANGE` in `portable-shader.ts`), so they carry no HDR uniform.
- **Composite reads:** never sample `u_sceneTexture` or `u_compositePrev` directly; go through `sampleScene()` / `compositeUV()` so a reduced render scale addresses the drawn corner (a test enforces this for post).
- **Pointer wiring:** every surface (editor canvas, `/embed`, `@wavr/gradient`, `@wavr/preview`) uses `attachPointer(element, engine)` from `@wavr/core`: Pointer Events on the element, never `window`, and `setPointerActive(false)` on leave.
- **GL context:** don't store the GL context or the engine in React state; use a ref.
- **Three.js:** the gradient engine is raw WebGL. Three.js / React Three Fiber is confined to the lazy-loaded 3D scene overlay (`components/Scene3DCanvas.tsx`).
- **Canvas callbacks:** `Canvas` tears down and rebuilds the WebGL engine whenever `onCanvasReady` / `onEngineReady` change identity. Pass `useCallback`s (as `app/editor/page.tsx` does), never inline arrows.
- **Hydration:** `/editor` is prerendered, so don't read `localStorage` or `window` in the first render of a client component. The mismatch forces React to throw away the server HTML (error #418). Read it after hydration, or through `useSyncExternalStore` with a server snapshot (see `lib/useTheme.ts`).
- **No backend:** Wavr is a client-only tool.

## Editor (`apps/editor`)

- **Store (`lib/store.ts`, Zustand):**
  - `set()` for continuous updates (sliders), `setDiscrete()` for one-shot changes (toggles, selects), `commitSet()` on pointer-up to close an undo step.
  - `lib/url-sync.ts` mirrors the schema-owned slice into the URL hash.
  - The zod-backed codec (decode, validate, encode) lives in `lib/url-codec.ts` and loads on demand through `loadUrlCodec()`. Keep `@wavr/schema` runtime imports other than `DEFAULT_CONFIG` out of `url-sync.ts`, `url.ts` and anything else in the initial bundle. That is why `applyHashToStore()` is async (it applies an empty hash synchronously). `/embed` bundles the codec statically.
- **Sidebar:** 5 tabs (Gradient, Effects, Presets, 3D, Shader), switched with keys 1–5, in the order of `SIDEBAR_TABS` (`lib/types.ts`).
- **Controls:** `components/ui/Slider.tsx` is a WAI-ARIA slider (Tab to it; arrows, Page Up/Down, Home/End; a held key is one undo step). Give it a `format` from `lib/units.ts` when its value has a unit (`times`, `degrees`, `px`, …); without one, a range inside 0–1 reads as a percentage of the value and any other range as the number itself, never as a share of the range. A layer's colours are edited on `components/ui/GradientBar.tsx`: the palette as the engine bakes it (`lib/color-stops.ts` calls `bakePalette`), with evenly spaced stops, since the palette has no stop positions; dragging a stop reorders, clicking the bar inserts the colour already there, and each is one `setDiscrete` undo step. The controls of a switched-off effect are hidden, not greyed out, and panel sections are always open (`components/ui/Section.tsx`). Accent colour is `--color-accent` only. Text colours meet WCAG AA (4.5:1) on every surface; check a new grey before using it. The canvas's render stats are off until asked for (S, or the command palette; `lib/useRenderStats.ts`). The editor fills the window edge to edge (`h-dvh`). The Effects tab has five sections: Light, Color, Lens, Pointer and Output; its "Bloom" is the cinematic bloom (`realBloomEnabled`). Effects the editor no longer offers (noise, the classic bloom and soft glow, ASCII, the shader 3D projection, ...) still render, and while a scene has one on, the tab lists it under "Also in this scene" with a switch to turn it off (`SCENE_EXTRAS` in `lib/scene-extras.ts`).
- **Lazy UI:**
  - The initial bundle is the canvas, top bar, layer panel, Gradient tab and timeline. Everything else (other tabs, modals, command palette, onboarding, mobile drawer body) is a `next/dynamic` import in `components/lazy.tsx`, which also exports `preload*` helpers for hover/focus and `prefetchEditorChunks` (one chunk per idle slot).
  - New modals and tabs go there. Mount a modal with `useEverOpened(open)` so it loads on first open and stays mounted afterwards.
- **Initial scene:** `lib/initial-scene.ts` is what `/editor` opens on; `url-sync.ts` applies it for an empty hash. It is the Aperture preset spelled out (no preset import in the initial bundle): the layer plus its grain, tone map, cinematic bloom, colour profile and HDR headroom (`INITIAL_EFFECTS`, spread into the store's defaults); `initial-scene.test.ts` keeps it equal to the preset. Core and schema defaults are separate (old URLs depend on them; their layer is a light wall on the old default colours), and a config without `realBloom` loads with bloom off, as the engine reads it.
- **Presets:** the catalogue is `PRESET_CATALOG` in `packages/core/src/presets/catalog.ts`, grouped strongest first (Light Fields, Light). Every id is exported, and `@wavr/gradient`, `@wavr/preview` and `create-wavr` accept them by name. Each card shows a pre-rendered 384×288 sRGB WebP from `apps/editor/public/presets/` whose URL carries a hash of the preset's config (`thumbnails.json`); after changing or adding a preset run `pnpm thumbnails` (`tests/parity/thumbnails.mjs`), or `presets.test.ts` fails.
- **HDR:** while the scene asks for headroom and the screen can show HDR (`lib/useHdrDisplay.ts`), `Canvas.tsx` imports the WebGPU output on demand and lays its canvas over the WebGL one. The WebGL canvas stays in place at `opacity: 0`, so it keeps the layout and the pointer. Attaching and detaching draw a frame at once, so the swap shows no blank frame. The Effects panel's caption reads the output's state from `lib/hdr-status.ts`. A patch that brings colours without naming a headroom is standard range (`loadPreset`). Only the editor presents HDR so far (`/embed`, `@wavr/gradient` and `@wavr/preview` don't yet).
- **Frame state:** `lib/frame-state.ts` (`applyTimeline`, `withPerformanceMode`, `applyEnginePerformanceSettings`) builds the per-frame state and applies the performance mode (`getEditorPerformanceSettings`: pixel ratio, frame cap, render scale; auto = adaptive 0.6–1). It's shared by `Canvas.tsx` and export, so exports match the live view. Nothing silently lowers the user's settings for speed.
- **Export:**
  - `lib/export.ts` handles PNG (1×/2×/4×) and GIF, both rendered offscreen at exact times.
  - GIFs are encoded by `lib/gif.ts` (median-cut palette, ordered dither, LZW) in `lib/gif.worker.ts`.
  - Code exports (React, web component, standalone player) are single-layer and warn about what they drop, but what they include is the engine's own code: `lib/portable-shader.ts` cuts the selected gradient, its mouse style, tone map and colour grade out of the engine's GLSL (`SHADER_PARTS`), and `lib/portable-runtime.ts` is the shared JS (palette bake ported from `palette.ts`, pointer smoother from `pointer.ts`). Don't hand-write export shader code; a new gradient mode needs no export change. `exportCSS` / Tailwind are plain CSS approximations.
- **Projects:**
  - `lib/projects.ts` stores projects in `localStorage` (`wavr-projects`). Uploaded images go to IndexedDB via `lib/image-store.ts`, and projects hold `wavr-image:<sha256>` references.
  - `saveProject`, `deleteProject` and `projectStateForLoad` are async and serialized; await them.

## Adding a Gradient Mode

The canonical list is `GRADIENT_TYPES` in `packages/schema/src/enums.ts` (zod-free). The schema, engine and preview derive their types and lists from it. Then:
1. `packages/core/src/engine.ts`: add a shader id to `GRADIENT_TYPE_IDS` (a type error until you do). The portable exports in `export.ts` reuse it.
2. `packages/core/src/shaders/gradients.glsl`: add the gradient function inside `#if WAVR_GRADIENT == <id>` … `#endif` (the guard line directly followed by `vec3 <type>Gradient(vec2 uv, float time) {`; comments above the `#if`; helpers in their own guarded block before it), and an `#elif WAVR_GRADIENT == <id>` branch in `computeGradient()`. Follow the house rules at the top of the file: a few broad, slow forms on aspect-corrected coordinates, map a field to the palette with `pingPong` or a sine (never `fract`), size pixel-scale details from `u_resolution.y`. Every mode but image is light. The light modes ("Light gradients": liquidChrome, iridescentFoil, horizonGlow, lightLeak, inkSmoke, plasmaOrb) read the palette as light, darkest stop first and brightest last, and their highlights may burn toward white. A new light mode gets a curated palette in `LIGHT_GRADIENT_PALETTES` (`layers.ts`) and presets in `presets/light.ts`. The light fields ("Light fields": aperture, halo, lightWall) add light instead of walking the palette: they work in linear light with the helpers in `common.glsl` ("Light": `lightStops`/`lightRamp` read the raw stops on a Catmull-Rom curve, `blurredBox` is an exact blurred rectangle, `lightToDisplay` rolls light past white toward white keeping its hue), and give every glow in closed form rather than as a blur. Aperture and light wall read their stops by role (`LIGHT_FIELD_PALETTES` / `LIGHT_FIELD_PALETTE_ROLES`); their presets (`presets/light-fields.ts`) set `toneMapMode: 0`, since the default tone map's shoulder dims saturated colours, `colorProfile: "display-p3"`, and an `hdrHeadroom` by how much of the frame is light (2 stops for a small light in a dark room, 1.5 for an opening in a wall, 1 when the whole frame is light: a screen holds a small bright area far brighter than a full one). If it reads `gl_FragCoord`, add it to `FULL_RESOLUTION_GRADIENTS` in `engine.ts`.
   Then add its `WAVR_MOUSE_WARP` line in `mouse.glsl` (an unknown id is a compile `#error`).
3. `packages/react/src/types.ts`: add it to the published `GradientType` union. This copy stays standalone so the `.d.ts` files don't depend on `@wavr/core`; `types.check.ts` fails `pnpm lint` if it drifts.
4. `apps/editor/lib/gradient-types.ts`: add a `GRADIENT_OPTIONS` entry, its tile in the Gradient tab's Look grid (light fields, then light modes, then image), with a one-line `description` of what it is and how it reads its colours. The tile shows the thumbnail of the preset whose id is the type's (`lookThumbnail`), so give the type a flagship preset of that id. Every type but image needs a curated palette (`LIGHT_GRADIENT_PALETTES` or `LIGHT_FIELD_PALETTES`; a type error until it has one): picking the look brings it (`lookPatch`, the store's `setLook`), Reset in Colors restores it, and Randomize (`randomLook`) picks a type, takes that palette and turns every stop's hue by one random angle in OkLCh (`rotateHue`), so the palette's roles hold.
5. Optionally, `defaultSoftnessForGradientType` in `packages/core/src/layers.ts`.

`apps/editor/lib/gradient-types.test.ts` fails if a type is missing an editor option, a shader id, a guard or a dispatch branch, or if a kept type's shader id changes (code exports and embeds compile it in).

To retire a mode, delete it everywhere and add its name to `RETIRED_GRADIENT_TYPES` (`packages/schema/src/enums.ts`) with the kept type it opens as. Every place a config enters reads that table (`migrate()` for share URLs and `/embed`, `parseSceneDocument()`, core's `resolveConfig()`, the editor's `projectStateForLoad()`), so old links, embeds and saved projects still open. A config field only the retired mode read goes from the schema too; `migrate()` and `parseSceneDocument()` drop it from old configs (`RETIRED_GLOBALS`, next to the table).

## Testing

- **Editor unit tests:** Vitest over `apps/editor/lib/**/*.test.ts`, in a Node environment. `.glsl` imports load as text.
- **Engine tests:** `lib/test-utils/fake-webgl.ts` is a recording fake WebGL 2 context (options: `parallelCompile`, `floatTargets`; `controls` to fail or finish compiles). Construct a real `GradientEngine` on it to assert draw targets, per-draw uniforms, bound textures, program creation and upload counts (see `engine-render-passes.test.ts`, `engine-programs.test.ts`, `engine-uniform-cache.test.ts`, `engine-capture.test.ts`). `engine-shader-sources.test.ts` reads the real `.glsl` files and checks the assembled sources: one gradient function per layer program, one `computeGradient` call, no gradient code in post.
- **Parity harness:** `pnpm test:parity` renders real frames on headless Chromium's SwiftShader. Its page compiles every gradient type before the first test, so a shader that fails to compile fails CI with the GLSL log. `tests/parity/goldens/` is empty, so until the `parity-generate` workflow commits goldens, each fixture only has to render a non-blank frame; once any golden exists, a missing one fails. Set `CHROMIUM_PATH` to use an existing Chromium. Any change to rendered output still needs a look (below), and a check on a real GPU (the Vercel preview works).
- **Snapshots:** `pnpm snapshots [dir]` (default `test-results/snapshots`) renders every gradient type (default layer; `image` gets a generated picture) and every parity fixture at t=1s, 512×512, with `engine.captureImageData`, and prints timing per image. Options (usage at the top of `tests/parity/snapshot.mjs`): `--only`, `--time`, `--size`, `--width/--height` or `--aspect`, `--palette <name|#hex,…>`, `--layer k=v,…`, `--state k=v,…`, `--presets`, `--scenes file.json`, `--scale`, `--bench N`, and pointer staging (`--mouse x,y`, `--stroke`, `--ripple`). `pnpm snapshots:diff <dirA> <dirB>` compares two runs; `SNAPSHOT_PAGE` points at another build of the page. Compare against a run from another commit when you touch shaders or the engine, and look at the PNGs.
- **Export parity:** `pnpm export-parity [dir]` renders each type through the engine and through the exported standalone player (or `--format web`) and prints the mean/max difference; it takes the snapshot options plus `--max-mean`. Run it after touching shaders, the palette or the pointer model.
- **HDR output:** `tests/parity/hdr.test.ts` (part of `pnpm test:parity`) runs the whole HDR path on SwiftShader: engine, pack pass, WebGPU decode onto an extended-range canvas, read back as half floats. Against a standard capture it checks that no headroom gives the standard frame and that two stops make the light four times brighter in linear light while the wall stays put. WebGPU there runs on SwiftShader's Vulkan (`--enable-features=Vulkan --use-vulkan=swiftshader --use-webgpu-adapter=swiftshader`); with the default backend, presenting any WebGPU canvas loses the device and the WebGL context with it. Headless Chromium reports a standard-range screen, so to see the editor attach its output, stub `matchMedia("(dynamic-range: high)")`.
- **Mouse styles:** `node tests/parity/mouse-probe.mjs` measures each warp style's peak displacement, reach and circularity; rerun it after changing style constants.
- **React package:** `packages/react` has Vitest with happy-dom (`packages/react/test`).

## Code Style

- TypeScript strict, no `any`
- Functional React components with hooks; Tailwind CSS for styling
- GLSL uniforms prefixed with `u_` (e.g. `u_speed`)
- Prefer `const` over `let`
- Match the comment density and idioms of the surrounding code
